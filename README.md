# Farmforge

A long-running browser farm/automation game. The farm is rendered in basic 3D with Babylon.js, while gameplay rules remain plain JavaScript. Accounts and persistent saves use Cloudflare Workers and D1.

## Gameplay

- An interactive 8 × 8 3D field with low-poly soil and animated growth stages.
- Click/tap a plot to plant wheat, then click ripe wheat to harvest.
- Drag on the scene to orbit the camera; scroll/pinch to zoom; use **Reset camera** to return to the default view.
- Keyboard access: focus the 3D canvas, move among plots with arrow keys, and press Enter/Space to plant or harvest.
- Sell wheat, buy the Harvester to automatically collect mature crops, and save progress across devices.
- All existing v1 JSON saves stay compatible; this update changes rendering, not save structure.

## Architecture

```text
public/
  index.html
  css/main.css
  js/
    main.js         # Browser bootstrap and state flow
    scene3d.js      # Babylon scene, meshes, camera and tile picking
    renderer.js     # HTML HUD only
    input.js        # Button input
    game.js         # Rules and state, independent of Babylon
    api.js          # API client and save manager
    data/           # Data-driven crops and unlocks
  build/game.js     # Generated by npm run build; do not edit or commit

src/
  worker.js
  api/auth.js
  api/save.js
  db/database.js
schema/schema.sql
tests/
  game.test.mjs
  smoke.mjs
wrangler.toml
```

Babylon is installed through npm as `@babylonjs/core`; a single small esbuild command bundles the client into `public/build/game.js`. The generated bundle is served by Cloudflare alongside the HTML and CSS, so the game does not depend on a third-party CDN at runtime. No front-end framework or asset models are required.

The 3D renderer reads `Game` state and only rebuilds crop meshes when their visual growth stage changes. Simulation and D1 persistence remain separate from the graphics.

## Local development

Use Node.js 22 or later.

```bash
npm install
npx wrangler d1 execute db01 --local --file=./schema/schema.sql
npm run dev
```

`npm run dev` builds the client and starts the Cloudflare Worker dev server. When changing the client, restart the command to rebuild, or run `npm run build` in another terminal.

## Testing

```bash
npm test
npm run build
```

The core tests cover planting, growth, harvest, sales, automation and save compatibility. The GitHub deployment additionally fetches the generated browser bundle from the live site and runs a register/login/save/load smoke test.

## Production

D1 `db01` is already configured in `wrangler.toml`. The GitHub Actions workflow runs on pushes to `main`, installs dependencies, builds the Babylon client, tests, initializes D1 schema if necessary, deploys the Worker and tests the live site. It requires two repository Actions secrets:

- `CLOUDFLARE_API_TOKEN` — token scoped to the Worker and D1.
- `CLOUDFLARE_ACCOUNT_ID` — Cloudflare account ID.

Manual production deploy with Wrangler authentication:

```bash
npm install
npx wrangler d1 execute db01 --remote --file=./schema/schema.sql --yes
npm run deploy
```

## Expanding the game

Define new crops in `public/js/data/crops.js` and unlocks in `public/js/data/upgrades.js`. Add rules to the standalone game simulation only when a new mechanic requires them. Keep new 3D meshes and visual assets in `scene3d.js` (or split out a clearly responsible module once it grows), without pushing gameplay decisions into the renderer.
